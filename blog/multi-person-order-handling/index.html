實務做法

店裡不只你一個人看單

兩個人都看過，不代表有一個人真的把它處理完。

作者：訂單秘書2026-09-06

一句話

多人看單要把「看過」和「已處理」分開：大家看同一份訂單台，用「待接單」指出還沒有人接手的單，修改則留下人與時間；誰負責哪一步仍要由店內自己訂規矩。

一人店漏單，常是忙到忘了抄。有員工的店不一樣：兩支手機都跳出同一則訊息，兩個人都看到了，也都覺得對方正在弄。隔天客人問貨在哪裡，才出現最熟悉的一句：「我以為你處理了。」

多人看單的幾個斷點
  1. 一人店與多人店不同
  2. 交接班怎麼斷
  3. 同一份訂單台
  4. 待接單的意義
  5. 員工改單怎麼查
  6. 角色權限做不到

一人店怕忘記，多人店怕責任漂走

你自己一個人看群，至少知道這筆單有沒有抄。忙到沒處理，是你回頭要補的事。店裡多一個人後，「誰看到」和「誰負責」被拆開：老闆在外面看過訊息，店員以為老闆已經收；店員回了一句收到，老闆以為店員已經加進總表。

LINE 的已讀不能回答這筆單現在走到哪裡。它只表示有人打開訊息，不表示品項對過、客人確認過，也不表示有人準備出貨。漏單各種斷法可先看漏單通常斷在哪一步；多人店要多補的是「誰接手」這一格。

交接班最容易留下兩個版本

早班接到客人電話，原本五箱改成三箱。他在紙上劃掉五，順手寫三；晚班打開 LINE 群，看到的還是原本五箱。另一種情況是老闆在外面用手機看群，店裡的人照櫃台上的紙備貨。手機裡的單已經改過，紙上沒有，兩份都像真的。

交接不能只說「今天沒什麼事」。每一筆口頭改單都要回到大家共同看到的地方。電話內容不會自己出現在系統裡，接電話的人仍要輸入；但只要輸入到同一份訂單，晚班就不必猜紙和 LINE 哪份比較新。

交接先問版本，不先問記憶

「你記得客人改幾箱嗎？」得到的是印象。「這筆最後一次修改是什麼？」才有共同紀錄可以查。

系統怎麼接：所有人看同一份訂單台

訂單台不是老闆一份、店員又一份。誰進去看，看到的是同一筆訂單與現在的狀態。有人修改時，誰改的、什麼時候改的會留紀錄。原本的「我以為你處理了」就能變成可查證的事：這筆是否還待接單、何時被改過、目前內容是什麼。

留紀錄的價值不是抓人，而是讓下一班不用還原現場。月底客人問「我明明後來改三箱」，也可以沿修改順序找，不必只看最後一格數字。匯出與核對的完整做法可看LINE 訂單月底怎麼對帳。

「待接單」不是裝飾，是沒有人接手的明確答案

忙的時候最浪費時間的問題是：「這家的單處理了沒？」問一圈沒人確定，最後只好重新翻群。待接單讓答案留在畫面上。只要還在這個狀態，就表示不能因為有人已讀而當成完成。

交班前可以只看待接單清單，把還沒接手的逐筆交出去。接班的人不必重讀全天每個群，也不用把早班說的話全部記住。若品項本身有問號，那又是另一個狀態：有人已接手，但內容還沒確定。把責任與內容分開，才不會一看到問號就以為完全沒人處理。

員工改單，最重要的是不要直接覆蓋到看不見

客人把五箱改成三箱，畫面最後顯示三箱不夠。晚班需要知道這不是最初就叫三箱，而是後來改過；月底對帳時也需要沿著紀錄回看。修改留痕讓這件事不再靠誰講得比較大聲。

但紀錄只能保存已經輸入的動作。客人在店門口口頭說一句，員工沒有寫回訂單台，系統不會知道。店裡仍要訂一條很普通的規矩：電話、現場或私訊改單，由接到的人立刻補進共同訂單。飲料長單與多單位特別容易在交接時看錯行，可對照飲料與酒水經銷的接單情境。

先講清楚：系統不管誰有權限改什麼

它不做角色權限；能進訂單台的人都能改

訂單秘書會留下誰在什麼時候改了內容，但不替你設定「只有老闆能改數量」「早班只能看、晚班不能刪」這類角色權限。誰能進訂單台，誰就都能修改。

所以店裡誰負責接單、誰能接受加單、交班前要清掉哪些狀態，仍是你自己的規矩。系統把動作留下來，不能代替分工；如果你需要細到每個職位只能動特定欄位，這裡幫不上。

多人管理不是把更多人加進畫面就完成。真正要補的是一條共同路徑：訊息進來先待接單，有人接手才往下走，任何修改留在同一筆紀錄。做到這三件事，「我以為你處理了」才有一個不靠印象的答案。
