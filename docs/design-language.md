# 訂單秘書設計語言

這份文件寫給三個月後接手網站的人。它不是重新定義品牌，而是把目前已經散落在首頁、產業頁與共用樣式裡的做法整理成一份可查的規則。若文件與實作衝突，先讀 `assets/trade.css` 與首頁 `index.html` 的內嵌樣式，再判斷差異是不是刻意的。

## 一句話掌握這套視覺

把批發現場的混亂，放進一張安靜、清楚、像帳冊的表。深色區塊承接承諾與判斷，淺色區塊把做法一件一件攤開；綠色只用來指路與確認，不拿來裝飾整頁。

## 色票與深淺節奏

所有顏色都從 `:root` 既有 token 取用。新增元件時先找語意相同的 token，不要另取一個「看起來差不多」的色值。

| Token | 色值 | 用途 |
|---|---:|---|
| `--ink` | `#0d1512` | 主深底。首頁 hero、判斷規矩、收尾 CTA、footer。也是 manifest 的 theme/background color。 |
| `--ink-2` | `#142019` | 深底上的卡片與媒體底，不拿來取代主背景。 |
| `--ink-line` | `#24352c` | 深底分隔線、邊框、ghost button 邊線。 |
| `--pine` | `#1e4d3b` | 品牌主色。品牌標底、淺底標籤、重要小標、表頭與主要結構。 |
| `--leaf` | `#3fa878` | 動作與正向狀態。主 CTA、深底 eyebrow、確認與可前進的提示。面積要小，才能保留注意力。 |
| `--leaf-strong` | `#46b985` | `--leaf` 元件的 hover 狀態，不當作另一個一般綠色使用。 |
| `--paper` | `#edf0ea` | 主淺底，也是品牌標在深色 tile 上的線條色。 |
| `--paper-2` | `#ffffff` | 淺底上的卡片、表格與交替 band。 |
| `--paper-line` | `#d4dbd1` | 淺底邊框與分隔線。 |
| `--paper-line-strong` | `#bcc9b9` | 淺色卡片 hover 時的較強邊界。 |
| `--text-on-paper` | `#16241e` | 淺底主文字。 |
| `--muted-on-paper` | `#55645c` | 淺底說明、註記與次要文字。 |
| `--text-on-ink` | `#e8efe9` | 深底主文字。 |
| `--muted-on-ink` | `#93a69b` | 深底說明、時間與次要資訊。 |
| `--cinnabar` | `#c05b4a` | 已發生的代價、麻煩編號、舊價格等「警示但不阻斷」資訊。不要拿來表示待確認。 |
| `--amber` | `#d8a03d` | 「還不能確定」的狀態，尤其 `？ 待確認`。它表示需要人看一眼，不等於錯誤。 |
| `--hairline-ink` | `rgba(232, 239, 233, 0.055)` | 深底方格紙紋理。只作低對比背景，不承載資訊。 |
| `--lift-shadow` | `0 10px 26px rgba(13, 21, 18, 0.09)` | 淺底卡片 hover 或輕微浮起。 |
| `--lift-shadow-ink` | `0 10px 26px rgba(0, 0, 0, 0.28)` | 深底卡片 hover。 |
| `--glow-leaf` | `rgba(63, 168, 120, 0.26)` | 主 CTA hover 的小範圍光暈。 |

頁面以 ink／paper 交替建立閱讀節奏：首屏先用 ink 說清楚承諾；中段在 paper 與白色 band 上拆解情境和做法；真正需要停下來判斷的三態規矩再回到 ink；最後以 ink 收束。不要連續堆很多深色 section，也不要把 leaf 鋪成大面積背景。

## 字型、字級與字重

- `--sans`：`Noto Sans TC` 優先，後接 `PingFang TC`、`Microsoft JhengHei`。用於正文、標題、按鈕與所有需要自然閱讀的中文。
- `--mono`：`IBM Plex Mono` 優先。用於數字、時間、價格、數量、標籤、eyebrow、section label 與鍵盤式指令。數量欄搭配 `font-variant-numeric: tabular-nums`，讓位數變化時欄寬不跳。
- 大標題與 section 標題使用 `900`，功能標題與 CTA 使用 `700`，正文以 `400` 為主，資料表標頭可用 `500`。不要用細字重營造「高級感」，這個站需要的是夜間與手機上也能快速讀懂。
- 首頁 `h1` 是 `clamp(30px, 7vw, 52px)`；產業頁 `h1` 是 `clamp(28px, 6.4vw, 46px)`。`h2` 約為 `24–34px`，正文基準 `16px / 1.7`，說明文字多為 `14–15px`，mono 標籤多為 `12–13px`。
- eyebrow 與 section label 使用約 `0.12em` 字距；一般中文標題只保留約 `0.01em`，不要過度拉開中文字。

品牌字標「訂單秘書」已在 `assets/brand/logo.svg` 與 `logo-mono.svg` 轉成 path；品牌資產中不要改回 `<text>`。

## 間距、圓角與陰影

這套系統目前沒有 spacing token；既有節奏本身就是規則。新增時先重用下列尺寸：

- `.wrap`：最大寬度 `1000px`，左右 padding `20px`。
- section：首頁通常上下 `64px`，產業頁通常 `60px`；hero 與 final 依版面略為加深。
- 元件內距：卡片多為 `20–22px`，表格橫向 `14–16px`，按鈕 `14px 26px`。
- 元件間距：同組卡片 `12–14px`，標題到說明 `8–12px`，區塊標題到內容約 `28–32px`。
- 圓角：品牌 tile 與小狀態 `6px`；按鈕與小卡 `8–10px`；主要卡片、表格、媒體 `14px`；價格卡 `18px`；pill 標籤才用 `999px`。
- 陰影只在需要區分層級時使用。一般卡片靠邊框；出貨表、媒體或 hover 才使用既有 shadow。品牌標與圖示不加陰影。

## 動效

所有主要進場都使用 `--ease-out: cubic-bezier(0.22, 0.61, 0.36, 1)`。動效的目的，是讓閱讀順序更清楚，不是表演產品功能。

- 首屏 `.fade-up` 只位移約 `14px`，不從透明開始；主標在慢速載入時也必須先看得到。
- 捲動進場使用 `data-rv`。只有在使用者沒有要求減少動態、瀏覽器支援 `IntersectionObserver`，且 `<html>` 已加上 `.js-anim` 時才隱藏並進場。
- 標準進場是 `18px` 往上、`0.6s`，透明度與位移共用 `--ease-out`。
- `data-rv-stagger` 每項約錯開 `0.07s`；真正有說話順序的對話可以用較長間隔。
- `prefers-reduced-motion: reduce`、沒有 JavaScript 或沒有 `IntersectionObserver` 時，內容必須完整、靜態且已可見。
- hover 位移只放在 `(hover: hover) and (pointer: fine)`，手機不製造假 hover。

## 三態標記：產品語言，不只是 UI

三態必須同時保留符號與文字，不能只靠顏色。這三個狀態描述的是訂單能不能往下走：

| 狀態 | 寫法 | 意義 | 顏色語意 |
|---|---|---|---|
| 已確認 | `✓ 對上了` | 品項、數量與單位已能對上；在需要客人確認的流程裡，仍要等客人按「✓ 沒錯」才成立。 | leaf／pine，表示可以前進。 |
| 待確認 | `？ 待確認` | 名稱、規格或語意對不到唯一答案。停下來請人看，不替使用者猜。 | amber，表示未定，不是錯誤。 |
| 不算訂單 | `— 不算訂單` | 回報庫存、閒聊、感謝或其他非叫貨內容，不進訂單。 | muted，刻意降低注意力。 |

不要把 `？` 改成警告三角形，也不要把 `—` 做成刪除或錯誤。核心承諾是「有把握才收；沒把握就問；不是訂單就安靜」。

對應圖示在 `assets/icons.svg`：`icon-confirmed`、`icon-needs-confirmation`、`icon-not-order`。24px 圖示用於需要圖形輔助的介面；小型文字標籤仍保留原本的 `✓／？／— + 文字`。

## 版面與內容節奏

- 內容永遠先進 `.wrap`，不要讓正文無限制拉寬。
- 一個 section 只回答一個問題：現場發生什麼、產品怎麼做、使用者要判斷什麼。
- 深色 section 的格線是低對比帳冊意象；只能當背景，不能提高到會和文字競爭。
- 卡片網格從手機單欄開始，`720px` 左右再展開；首頁複雜網格在 `940px` 才進四欄或三欄。
- 先讓靜態 HTML 完整可讀，再加動效、影片與 JavaScript。任何 enhancement 失效時，文案與主要連結仍必須工作。

## 品牌標用法

品牌標是**一個問號**（2026-09-06 從三個方向裡選定）。理由：這個產品唯一真正
與眾不同的地方是「沒把握就標起來問你一句，絕不亂猜」——市面上的接單工具都在
比功能多，只有我們在講這件事。把那個承諾直接畫成標記，比畫一張清單有力。

它的代價要知道：問號是通用符號，單獨看不會讓人聯想到訂單，**必須跟「訂單秘書」
四個字一起出現才成立**。所以不要單獨使用純 mark 當作對外識別（favicon 與 app icon
例外，那些場合旁邊本來就有頁面標題或 App 名稱）。

被換掉的方向 A（三列清單）與方向 C（多筆收斂）留在 `assets/brand/mark-a.svg`、
`mark-c.svg`，比較表在 `contact-sheet.html`（不上線）。要重新評估時有東西可看。

### 檔案

| 檔案 | 用途 |
|---|---|
| `mark.svg` | 純符號，`currentColor` 描邊 |
| `mark-tile.svg` | pine 圓角 tile 加 paper 符號。LINE 頭像、簡報等外部場合用 |
| `logo.svg` | 彩色橫式組合，**淺底專用** |
| `logo-on-ink.svg` | 淺色橫式組合，**深底專用** |
| `logo-mono.svg` | 全 `currentColor` 單色版，見下方警告 |
| `favicon.svg` | 依瀏覽器深淺模式反轉 pine 與 paper |
| `favicon-16/32.png`、`apple-touch-icon.png`、`icon-192/512.png` | 由 `tools/make-brand-icons.py` 產生 |

### `currentColor` 的陷阱（踩過）

`logo-mono.svg` 只有在**直接 inline 進 HTML** 時才會跟著文字顏色走。
用 `<img src="logo-mono.svg">` 載入時，SVG 是一份獨立文件，`currentColor`
會解析成**黑色**——放在深色背景上等於看不見。
`<img>`、簡報、Word、email 這類場合請用 `logo.svg`（淺底）或 `logo-on-ink.svg`（深底）。

### 改標記時怎麼做

幾何的單一來源是 `tools/make-brand-icons.py` 裡的 `mark_polylines()`。
改完跑一次 `python3 tools/make-brand-icons.py`，五張 PNG 會一起重產並自我驗證
（尺寸、對比、apple-touch-icon 的不透明）。SVG 那幾支要手動同步，
19 支 HTML 導覽列的 inline SVG 也要一起換。

註：PNG 不是用 `ImageDraw.line(joint="curve")` 畫的——那個做法在轉折處會留下
鋸齒狀缺口（512px 的問號弧線上看得很清楚）。改成沿路徑密集蓋圓，
等價於 `stroke-linecap:round` + `stroke-linejoin:round` 且沒有接縫。

### 使用規則

- 純 mark 最小 `16px`；導覽列 tile 固定 `28px` 容器；橫式 logo 建議不要小於 `136px` 寬。
- 四周至少保留 mark 高度的四分之一作為留白；不要讓文字、框線或裁切貼到 tile。
- 保持原始比例。不可拉寬、壓扁、旋轉、重畫線寬、加漸層、陰影、3D、外光或換成色票外顏色。
- 導覽列維持「mark tile + HTML 品牌名稱」，不要換成整張橫式 logo；這樣文字仍能隨頁面字級與可及性設定工作。

## UI 圖示

`assets/icons.svg` 是 24×24、2px 線寬、圓端點圓接點的單色 sprite。圖示只使用 `currentColor`，由放置它的元件決定深淺底顏色。不要在單支圖示內加第二色、填滿大色塊或陰影。

```html
<svg width="24" height="24" aria-hidden="true">
  <use href="/assets/icons.svg#icon-order-card"></use>
</svg>
```

圖示用來加速辨識，不能替代文字標籤。功能名稱、狀態與 CTA 仍要有可讀文字。

## 文案語氣

文字是這個站最重要的品牌資產。改寫或新增前，用這五條檢查：

1. 對使用者說「你」，不說「企業用戶」「客戶端」或抽象的第三人稱。
2. 先講具體場景與動作：晚上十點、往上滑、撿貨、裝簍、月底對帳。少用「高效、智能、強大、無縫」這類形容詞。
3. 說清楚系統做什麼，也主動說它不做什麼。可以自曝其短，例如不碰金流、物流、庫存，不假裝完整。
4. 不用「賦能、痛點、解決方案、數位轉型」；也不要用通用 SaaS 口號蓋過現場語言。
5. 不確定性要直說。不是「AI 智慧判斷」，而是「沒把握就標一個 `？` 請你看一眼」。

最終檢查很簡單：食材行、材料行或耗材行的老闆，能不能在手機上掃一遍就知道這段在說哪一刻、哪一筆單、要做哪一個動作。如果只能看出品牌很厲害，卻看不出產品實際做什麼，就不符合這套語言。
